## Что это за проект (факты, не приукрашивать)

PAYPHONE — экспериментальный **IPv4 VPN** на Rust, **v0.2.0**. IP-пакеты из TUN едут в **QUIC datagrams** (Quinn) под **TLS 1.3**. Сессии открываются **Ed25519-токеном** подписки, не логином.

Репозиторий: https://github.com/digkill/PAYPHONE

Семь крейтов: `payphone-core`, `payphone-auth`, `payphone-token`, `payphone-transport`, `payphone-tun`, `payphone-server`, `payphone-client`.

Внутри: `10.77.0.0/24`, сервер `10.77.0.1`. Снаружи на проде типично **443/udp** (обфусцированный QUIC) и **443/tcp** (лендинг и/или REALITY). В контейнере порты `40404` / `40443`.

Полный туннель: forwarding + MASQUERADE на сервере; на клиенте два маршрута `/1` (`0.0.0.0/1` и `128.0.0.0/1`) через TUN. Default не трогаем.

Платформы клиента: macOS, Linux, Windows (`wintun.dll`, админ). IPv6 с клиента **глушится** blackhole `::/1` + `8000::/1`, чтобы браузер не уехал на домашний AAAA. В туннеле IPv6 **нет**.

Прод: домен вроде `ph.sorapure.fun`, Let’s Encrypt через `PAYPHONE_TLS_DOMAIN` (TLS-ALPN-01 на том же 443). Клиент с hostname в `--server` сам берёт публичные CA (`--tls-ca system`). Дефолт в репе по-прежнему self-signed `localhost` + pin `dev-certs/payphone-cert.der`.

## Два транспорта — не путать

1. **UDP 443 (дефолт клиента).** QUIC + тонкий XOR с общим PSK: salt, length, случайный хвост 0–32 байт. Без секрета сокет **молчит**. Это ломает сигнатуру QUIC и слепой probe. Это **не** сайт и **не** шифр: конфиденциальность уже у TLS 1.3. На проводе остаётся долгоживущий UDP 4-tuple.

2. **TCP 443.** Браузер делает GET — маленькая HTML-страница («Follow the white rabbit.»). Клиент `PAYPHONE_TRANSPORT=tls` после TLS шлёт кадры PAYPHONE, не HTTP. Опционально **REALITY** (`PAYPHONE_REALITY=on`, в Coolify по умолчанию **выкл**).

## REALITY vs VLESS — обязательно объяснить, иначе статья врёт

Это **разные слои**. Не пиши, что «для DPI нужен VLESS» или что PAYPHONE «неполноценный без VLESS».

- **REALITY (снаружи):** Xray-совместимый `session_id` в ClientHello (X25519 + HKDF-SHA256 `"REALITY"` + AES-256-GCM). Проба без auth **TCP-splice** на `PAYPHONE_REALITY_DEST` (живой TLS 1.3 сайт с VPS). Свой клиент: ephemeral Ed25519, HMAC-SHA512 как `VerifyPeerCertificate` у Xray. ClientHello как uTLS Chrome 131 (GREASE по краям, shuffle в середине, GREASE ECH, настоящий ML-KEM-768 public + X25519) — **не** побитовый дамп живого Chrome. ServerHello dest, патч только X25519 `key_share` (JA3S dest). Размеры зашифрованного хвоста и post-handshake копируются (три ALPN-пробы dest). EncryptedExtensions **plaintext dest не копируем** — он внутри AEAD, ключей dest нет; эхоим ALPN клиента.

- **VLESS (внутри, у Xray):** после TLS клиент просит «открой TCP/UDP сюда». Сервер — прокси запросов приложений, не TUN. **В PAYPHONE этого нет и не будет в этой статье как TODO.** Внутри после REALITY всё равно кадры PAYPHONE (`WhatsUpDude` / `Data` / …). Xray-клиент с теми же ключами пройдёт наружный handshake и упрётся в чужой протокол. Так задумано.

- **Vision/XTLS** не делать и не обещать.

Смысл абзаца для читателя: маскировка «как чужой сайт» — REALITY. Совместимость с v2rayN/Hiddify — VLESS. PAYPHONE сознательно взял первое и не взял второе, потому что это VPN со своим клиентом, не ещё один inbound Xray.

## Протокол (коротко, без RFC-простыни)

16 байт заголовка: version, type, flags, length, sequence. Big-endian, жёсткие лимиты.

Кадры: `WhatsUpDude`, `AllGoodDude`, `BackAgainDude` / `StillGoodDude`, `AccessDeniedDude`, `Data`, `Ping`/`Pong`, `Rekey`, `Close`. Resume-файл клиента шифруется от PSK. Сессии сервера на диске. Revoke — файл `token_id`. Лимит устройств и Mbps из токена энфорсятся.

Почему datagrams, не streams: IP уже умеет терять пакеты; stream = TCP-over-TCP. Quinn при переполнении дропает старые datagrams — для туннеля это правильнее. Баг: `send_datagram_wait` блокировал select; лечится `send_datagram` и дропом `TooLarge`.

## Обязательные боевые истории (без них статья пустая)

Раскрой каждую: симптом → ложная причина → настоящая → фикс. Это ядро текста.

1. **MTU.** «1280 потому что IPv6» не влезает в QUIC datagram (пол ~1200 UDP + оверхед Quinn + 40 байт кадра PAYPHONE). На проде клиент умирал на толстом браузерном пакете. Сейчас TUN **1100**. Гигабита не будет, пока MTU не поднимется после path-MTU.

2. **Паддинг-бакеты.** Округление длин до `[128, 296, 568, 1200, 1440]` ломало PMTU Quinn: проба 1200 прыгала в 1440. Сейчас хвост равномерный 0–32.

3. **macOS и маршрут к серверу.** `networksetup` пересобирает таблицу; host-route к VPS пропадает; `/1` заглатывает IP сервера; QUIC уходит в свой utun. Scoped `-ifscope` Quinn не видит. Watchdog `sleep` внутри `select` под трафиком не крутился. Фикс: не трогать `networksetup`; IPv6 blackhole; DNS через `scutil`; unscoped `/32`; `IP_BOUND_IF`; отдельный interval 400 мс.

4. **Ctrl+C.** Tokio ест SIGINT; `wait_idle` при живых `/1`; второй Ctrl+C никто не слышит; интернет мёртв. Снимать маршруты **до** прощания с QUIC, `wait_idle` с таймаутом.

По желанию коротко: Windows NRPT (иначе DNS отвечает LAN-резолвер), optional `--kill-switch`, Docker Hub 429 на Coolify `build --pull` и базовые образы с Public ECR — только если влезает в объём, не вместо историй про маршруты.

## Чего не делать

- Не инструкция по обходу цензуры, не сравнение «нас не банят». DPI описывать как класс детекта (сигнатура, активный probe, JA3S), без рецептов «как пролезть».
- Не обещать VLESS, Vision, IPv6 в туннеле, бамп версии, «скоро как Xray».
- Не писать, что REALITY включён на проде: в Coolify он **выкл**, пока нет dest+ключей; своё DNS-имя должно оставлять лендинг и ACME.
- Не вставлять секреты, IP админки Coolify, токены API, PSK, приватные ключи.
- Не копировать большие куски кода; если листинг — 5–15 строк и зачем они.
- Не превращать статью в сравнительный обзор VPN. AmneziaWG и VLESS/Xray нужны для объяснения контекста и мотивации проекта, а не для неподтверждённых оценок скорости, качества или устойчивости к блокировкам.
- Не английский abstract в начале. Не эмодзи в заголовках.
